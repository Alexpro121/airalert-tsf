# AirAlert-TSF

Оцінка ризику повітряної тривоги як бінарної класифікації часових рядів.
Ціль: `Y_t = max(A[t..t+2])` (H=3). Головна метрика — PR-AUC.

## Семантика моменту прогнозу

Прогноз у момент T (початок години t): відомі стани `A[..t-1]`, ціль —
поточна година плюс дві наступні. Мертвої години немає. Усі ознаки через
`shift(>=1)`, ембарго H між train/test і всередині фолдів
(`TimeSeriesSplit(gap=H)`).

## Дані

- Реальні: volunteer-дамп Vadimkin (oblast-рівень, з 2022-02-25; за README
  джерела всі часи в UTC, у файлі всі строки з offset — перевірено
  115787/115787). Нічний пік підтверджено емпірично: 0.148 (23–06) проти
  0.106 вдень за Києвом. `main.py --real`.
  Наївні часи трактуються як Europe/Kyiv. Хвіст `tail_cutoff_hours=6` відрізано
  (цензурування справа). Кожен файл має поруч `.meta.json` з `source`.
- Синтетика (seed + фіксований кінець, детермінована): лише `--synthetic`,
  пише в `data/raw/alerts_synthetic.csv` і **ніколи** не чіпає `alerts.csv`.
- Сітка будується `[floor(min_start), ceil(max_end))`: остання година сітки
  може бути неповною (хвіст зрізу), початок — завжди повна година.
- Без прапорців і без файлу — явна помилка, тихого fallback немає.
- `alerts.in.ua active.json` не використовується (лише поточна секунда).

## Ознаки (57)

Календарні за **київським** часом: hour_sin/cos, dow_sin/cos, is_night (23–06).
Лаги 1,2,3,6,24. Вікна 3/6/12/24. `hours_since_last` (clip 168) + `has_history`.
8 коридорів t-1/t-2/sum3 без таргета, `country_ratio`, `nbr_new_onset`.
Трекер шляхів: 6 коридорів (east, northeast, southeast, south, west, southwest);
на кожен — дистанція найближчої тривоги до Києва (`path_*_dist`) і тиск хвилі
(`path_*_count`) + глобальна `min_threat_dist`. Хвиля Суми→Чернігів→Київська обл
виглядає як спад дистанції 3→2→1. Адаптивні `trail_168h` / `trail_720h`.
`has_threat_mention` / `has_all_clear` (стеми; 0 без файлу; `--text-signals`).

A/B path-трекер (real, OOF+holdout): OOF 0.4365→0.4393, holdout 0.6253→0.6402
(+0.015), gain path-фіч 6.7%. Лишено: покращення невелике, але консистентне.

## Моделі

heuristic (сусіди), persistence (`Y=lag_1`), always (prevalence-бейзлайн),
climatology (середнє за годиною доби), dummy_logistic (календар),
main = LightGBM (без `scale_pos_weight`; fallback — HGB, єдина фабрика
для OOF і фіналу). Поріг: argmax F2 за умови `precision >= max(0.25,
1.2 × prevalence_OOF)` (з Settings), нічиї — вищий поріг. Якщо жоден поріг
не проходить guardrail — береться поріг з максимальною precision
(нічиї — вищий; при всіх precision = 0 це 0.9), випадок логується як warning.
Вироджені точки (pred_rate > 0.99 або TN == 0) відхиляються strict-режимом;
якщо OOF-поріг все одно лякає 100% тесту — пайплайн бере стандартний 0.5,
пише ERROR в лог і мітить `degenerate_fallback: true` у `metrics.json`
(ранжування при цьому не страждає, страждає тільки бінарна точка).

## Інтерактивний прогноз (браузер)

```cmd
uv run python app.py
```

Відкрий http://127.0.0.1:8000 — там поле години (київський час), кнопка
«Прогноз», контекст (що було годину тому, сусіди, ніч) і графік ризику
за останні дні. Сервер бере навчену модель з `reports/model.pkl` і рахує
ті самі 32 ознаки, що й пайплайн. Працює тільки в межах дат дампа
(див. рядок статусу вгорі сторінки); новіші дати — після
`main.py --real`. Тільки цільовий регіон моделі (Київ): чужі регіони
київською моделлю не прогнозуються. API: `GET /api/status`,
`GET /api/predict?ts=2026-10-09T20:00`, `GET /api/history?days=3`.
